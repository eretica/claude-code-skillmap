# claude-code-skillmap

Claude Code の利用状況 — 特に**スキル・サブエージェント・MCP・スラッシュコマンドの活用度** — をチームで可視化するためのブラウザアプリ。

「誰がどの機能をうまく使っているか」を見えるようにして、チーム全体の活用モチベーションを上げることが目的です。

## 2つのモード

| | ローカル版(デフォルト) | クラウド版(`--mode cloud`) |
|---|---|---|
| 用途 | 個人で確認 / JSONを手動で交換 | チームで常用(メイン) |
| 通信 | **ゼロ**(完全ブラウザ内) | サマリーJSONのみをAPIへ送信 |
| チーム集計 | エクスポートしたJSONを手動ドロップ | 「チームに共有」ボタン → DBに保存され全員に反映 |
| 認証 | なし | ベーシック認証(Vercel Middleware) |
| DB | なし | Neon Postgres (Vercel Marketplace, 無料枠) |

どちらのモードでも**トランスクリプトの解析はブラウザ内で完結**し、扱われるサマリーは**ホワイトリスト方式**: 機能名(スキル名・ツール名・コマンド名・モデル名)と集計値のみ。会話本文・thinking・ツール引数/結果・ファイルパス(`cwd`/`gitBranch`)・セッションIDは**一切含まれません**(クライアント実装 `src/lib/parser.ts`、サーバー側でも受信時に再検証 `api/_lib/sanitize.ts`)。

## ローカル版の使い方

```sh
npm install
npm run dev   # 開発サーバー
npm run build # dist/ に静的ファイルを出力(任意の静的ホスティングで配布可)
```

## クラウド版のデプロイ (Vercel)

1. このリポジトリをGitHubにpushし、Vercelでプロジェクトとしてimport(Framework: Vite。ビルド設定は `vercel.json` が自動適用)
2. Vercelダッシュボード → **Storage → Create Database → Neon (Postgres)** を無料枠で接続(`DATABASE_URL` が自動設定される)
3. **Settings → Environment Variables** に以下を設定(管理画面用。リポジトリには置かない):
   - `BASIC_AUTH_USER` — ベーシック認証のユーザー名
   - `BASIC_AUTH_PASSWORD` — ベーシック認証のパスワード
4. デプロイ → `/admin`(ベーシック認証)でルームを作成し、発行されたルームURLをチームに共有

### アクセス制御(ルーム方式)

| パス | 認証 | 内容 |
|---|---|---|
| `/` | なし | ランディングのみ。データは一切表示しない |
| `/r/<room_id>` | ルームIDが実質のカギ | チーム用アプリ本体(個人解析・チーム集計) |
| `/admin` | **ベーシック認証** | ルームの発行・一覧(メンバー数・最終共有)・削除 |

- ルームIDは128bit乱数(22文字)で推測不能。存在しないIDへのAPIアクセスはすべて404
- ルーム削除でそのルームの共有データも消えます(CASCADE)
- 検索避け: 全レスポンスに `X-Robots-Tag: noindex, nofollow`、URLからの漏洩対策に `Referrer-Policy: no-referrer` を付与(`vercel.json`)
- 注意: ルームURL自体が秘密です。公開の場に貼らないでください

各メンバーの使い方: ルームURLにアクセス → 「個人解析」で `~/.claude/projects/` を読み込み → 表示名を入れて「チームに共有」。「チーム集計」タブに全員分が自動表示されます。

### クラウド版をローカルで動かす

```sh
npm run dev:cloud        # フロント (/api は localhost:8788 へプロキシ)
vercel dev --listen 8788 # API (要 vercel login と DATABASE_URL)
# DBなしで試すだけなら: npx tsx e2e/mock-api.ts (インメモリのモックAPI)
```

## テスト

```sh
npm test       # ユニットテスト (vitest): パーサ・除外・sanitizeの機密リーク検査を含む
npm run test:e2e # E2E (Playwright): 解析→除外→共有→チーム集計→項目削除の一連の流れ
```

GitHub Actions (`.github/workflows/ci.yml`) でpush/PR時に両方+ビルドを実行します。

### 1. 個人解析(各メンバー)

1. アプリを開き「個人解析」タブで `~/.claude/projects/` フォルダを選択(またはドラッグ&ドロップ)
   - macOS Finderでは `Cmd+Shift+.` で隠しフォルダを表示できます
   - 一度選ぶとフォルダを記憶するので、次回からは「↻ 前回のフォルダを再解析」ワンクリックで更新できます(表示名も記憶)
2. 自分のダッシュボード(スキル利用・サブエージェント・日別アクティビティ・トークン等)を確認
3. 「送信内容を確認」で実際に出力されるJSONの現物を確認できます(除外設定の反映もここで見える)
4. 表示名を入力して「サマリーJSONをエクスポート」

### 2. チーム集計(集める人)

1. メンバーからサマリーJSON(1人あたり数KB)をSlack等で集める
2. 「チーム集計」タブに全員分のJSONをドロップ
3. スキル×メンバーのマトリクス(空欄 = 布教チャンス)、スキル利用セッション率、活用機能の種類数などを比較

## 見られる指標

- **個人**: セッション数 / スキル利用回数・種類 / スキル利用セッション率 / **委任度**(サブエージェント側の処理比率) / サブエージェント・MCP・スラッシュコマンド・**プラグイン**の内訳 / **自分の成長トレンド**(週次のスキル利用セッション率・機能種類数) / **モード・権限モード利用** / **セッション長の分布** / **セッション実時間の分布** / **推論エフォート** / **ツール失敗率** / **利用環境(エントリポイント)** / Web検索・フェッチ回数 / 日別アクティビティ / **トークンの日別推移** / モデル別トークン / **概算コスト(API従量課金換算・単価は編集可)** / 組み込みツールの使い分け
- **チーム**: 機能×メンバーのヒートマップ(スキル/サブエージェント/MCP/コマンド/プラグインを切替、比較対象メンバーの列をハイライト、**機能名の絞り込み・メンバー列クリックでの並べ替え**対応) / **個人 vs チーム比較**(メンバー選択式、基準を**チーム平均か特定メンバー(1対1)**で切替、中央値・順位付き) / **「〇〇へのおすすめ」**(チームで使われているのに本人が未使用の機能) / **「この人に聞こう」**(機能を選ぶとよく使う人が分かる) / **日別アクティビティのメンバー重ね合わせ** / スキル利用回数・セッション率・活用機能の多様性・**委任度**ランキング / メンバー別トークン比較 / **モデル × メンバー**(利用モデルの内訳比較) / **メンバー別 概算コスト**(単価はブラウザ内のみで共有されない)
- **期間フィルタ**: 個人・チームとも「全期間 / 直近30日 / 直近7日」で切替可能(個人側は表示のみに適用され、共有・エクスポートは常に全期間)。機能利用の期間集計はサマリー内の日別カウント(`dailyFeatures`)を使うため、旧形式のサマリーは全期間値で表示されます(再共有で対応)
- **リポジトリ別表示**: 基本はリポジトリ横断の集計で、チーム集計の**リポジトリフィルタ**を選ぶと全指標(ヒートマップ・比較・ランキング・日別)がそのリポジトリ内に絞られます。「リポジトリ × メンバー」ヒートマップで誰がどのリポジトリで使っているかも一覧できます。記録されるのは**cwdの末尾ディレクトリ名のみ**(フルパスは含まれない)で、共有したくないリポジトリは除外パネルでチェックを外せます(トークンはリポジトリ別に分解できないため常に全体値)
- **セッション詳細(ローカル閲覧のみ)**: 個人解析でセッションを選ぶと、プロンプト→スキル読込→エージェント起動→ツール実行の流れをOpenTelemetryのトレースビュー風のウォーターフォールで表示します。スキルは帰属情報(`attributionSkill`)から「動いていた区間」の帯として、サブエージェントは `subagents/` 配下の自身のトランスクリプトから実時間の帯として描画し、行クリックでツール内訳を展開できます。5分以上のアイドルは圧縮表示。下部に累積消費(概算コスト/総トークン)のステップチャートと、**サブエージェント呼び出し一覧**(種別・モデル・所要・トークン・概算コスト・prompt文字数)も表示します。**この画面は共有・エクスポートとは完全に別系統**で、内容がブラウザの外に出ることはありません
- **URLで状態共有**: タブ・期間・カテゴリ・比較対象はURLハッシュ(例 `#tab=team&period=7`)に載るので、「今週のチームビュー」をリンクとしてSlack等に貼れます

## 共有のコントロール(クラウド版)

- **2ステップ共有**: 解析してもDBには入りません。ダッシュボードで内容を確認してから「チームに共有」を押して初めて保存されます(JSONエクスポートも常に併用可)
- **リポジトリはopt-in(誤爆防止)**: リポジトリは既定で全て未選択。「共有する内容を選ぶ」パネルで含めたいものだけをチェックします。1つも選ばずに共有しようとするとパネルが開いてエラーになり、選択を促されます(機密リポジトリを誤って含めないため)。選択はブラウザに記憶され、新しく現れたリポジトリは安全側でOFFのまま
- **共有前の除外**: 「共有・エクスポートから除外する項目を選ぶ」パネルで、公開したくないスキル・コマンド・サブエージェント・MCP・プラグインをチェックで外せます(エクスポートにも適用)。除外設定はブラウザに記憶され、再共有時にも過去の共有分ごと適用され続けます
- **共有後の削除**: チーム集計のヒートマップで「項目を削除する…」を押して**削除モード**にすると、数値セルのクリックでその人のその項目だけをサーバーから削除できます(通常時は誤操作防止のためクリック無効)。ただし本人が再共有すると直近期間の分は復活しうるので、恒久的に非公開にしたい項目は**本人の除外設定**を使ってください。メンバーチップの×でその人の全データ削除も可能
- **再共有 = 日付マージで蓄積**: 同じ表示名で共有し直すと、保存済みデータと**日付単位でマージ**されます(重複日は新しい解析を採用、古い日はそのまま残る)。ローカルのトランスクリプトは `cleanupPeriodDays`(既定30日)で消えますが、**共有し続ける限りDBには全履歴が蓄積**されます。マージはブラウザ側で行うため、除外した項目名がサーバーに渡ることはありません

### 過去履歴のバックフィル (stats-cache.json)

トランスクリプトが削除済みの期間でも、`~/.claude/stats-cache.json` に日別アクティビティ(セッション・メッセージ・ツール呼び出し数)が残っていることがあります。個人解析の「過去履歴を追加 (stats-cache.json)」からこのファイルを選ぶ(または `~/.claude` ごとドラッグする)と、その期間をバックフィルして長期トレンドを初回から表示できます。スキル等の内訳とトークンの入出力別は含まれないため、それらは共有開始以降のみ蓄積されます。スキル利用セッション率はスキル情報を持つ日だけで計算するので、バックフィルで希釈されることはありません。

### データの保持について

- ローカルの `~/.claude/projects/` は既定で**30日**で自動削除されます。ローカル保持を伸ばしたい場合は `~/.claude/settings.json` に `"cleanupPeriodDays": 365` などを設定してください
- DB側は日付マージにより蓄積されます。データ量は日別レコードで1人あたり**年間200〜400KB程度**なので、Neon無料枠(512MB)で数十人×数年は余裕です
- 最低でも30日に1回共有すれば履歴が途切れません(間が空くと、その間のローカル削除済み期間は記録されません)
- 日付は閲覧者のローカルタイムゾーンで区切ります。時差のあるメンバーが混在するチームでは日の境界が人によってずれます(同一タイムゾーンのチームを想定した割り切りです)

## データソース

`~/.claude/projects/**/*.jsonl`(Claude Codeのトランスクリプト)から以下だけを抽出:

| 指標 | 抽出元 |
|---|---|
| スキル | `tool_use` (`name=="Skill"`) の `input.skill` |
| サブエージェント | `tool_use` (`name=="Agent"`/`"Task"`) の `input.subagent_type` |
| MCPツール | `mcp__<server>__<tool>` 形式のツール名 |
| スラッシュコマンド | user行の `<command-name>` タグ |
| プラグイン | スキル名/コマンド名の `plugin:` プレフィックス |
| モード / 権限モード | `mode` / `permission-mode` 行(セッション数ベース) |
| 利用環境 | assistant行の `entrypoint`(セッション数ベース) |
| セッション長 | セッションあたりassistant行数の分布 |
| セッション実時間 | セッション内の最初と最後のタイムスタンプの差の分布 |
| 委任度 | assistant行の `isSidechain`(サブエージェント側メッセージの比率) |
| 推論エフォート | assistant行の `effort`(メッセージ数ベース) |
| ツール失敗 | user行の `tool_result` の `is_error`(回数のみ、エラー内容は非収集) |
| セッション詳細 | `attributionSkill`(スキル帰属区間)・`ai-title`・`subagents/agent-*.jsonl`(ローカル表示のみ、共有されない) |
| リポジトリ | assistant/user行の `cwd` の末尾ディレクトリ名のみ |
| トークン | assistant行の `message.usage` / `message.model` |

> 注意: `~/.claude/settings.json` の `cleanupPeriodDays` の設定によっては古いトランスクリプトが自動削除されるため、残っている期間分のみ集計されます。
